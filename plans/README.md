## Dependency notes

- Plan 001 comes first because current tests mostly model helpers in isolation and cannot distinguish a physics/data discontinuity from a Chart.js layout or redraw discontinuity.
- Plan 002 uses the runtime seam from Plan 001 to assert equal plot origins and label fit. It does not depend on the rendering-rate decision, but the shared test harness should land first.
- Plan 003 depends on Plan 001 and must preserve the axis contract from Plan 002 once it exists. Do not tune interpolation or redraw rate without the scheduler and canvas measurements from Plan 001.

## Findings considered and rejected

- Physics/RK4 equations are not a confirmed source of the visual defect. `stepPhys()` uses bounded substeps and the existing physics tests cover the model; do not change governor or swing-equation code as part of these plans.
- Chart.js's configured `animation.duration: 150` is not, by itself, proof of competing animation: every live chart commit calls `update('none')`, which disables the update animation mode. Measure before removing or re-enabling animation.
- Raising redraw frequency blindly is rejected. The repository previously reduced chart work because 60 Hz full redraws caused lag; the fix must measure frame cost and preserve a bounded render budget.
- `smartDecimate()` is not automatically wrong. It does not preserve extrema and its sampled identities shift as the rolling buffer shifts, so Plan 003 must test fault steps and extrema before changing it rather than replacing it on assumption.
